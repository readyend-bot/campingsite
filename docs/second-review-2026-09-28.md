# 두 번째 오류 검토

2026-09-28 · 수정 버전 0.1.2

후속 변경: 2026-09-29 사용자 지시에 따라 0.1.3에서 입실일 당일의 오후 2시 전 입실을 다시 허용했다. 아래 0.1.2 기록의 14시 제한은 현재 규칙이 아니다. [현재 변경 내역](early-check-in-2026-09-29.md)을 따른다.

사용자가 오류가 남아 있는지 다시 검토해 달라고 요청했다. 0.1.1의 화면 검토에 이어 연속 조작, 입퇴실 시간 경계, 저장 실패, 손상된 파일과 복원 직후 상태를 확인했다. 발견한 문제는 소스와 회귀 테스트에 반영했다. 모든 가능한 환경에서 오류가 없다는 보증은 아니며, 아래의 실제 확인 범위를 따른다.

## 발견한 문제와 수정

| 문제 | 수정 |
|---|---|
| 같은 자리에 오전 퇴실 손님과 오후 장박이 있으면 오전에도 장박을 먼저 표시 | 배정·장박·사용중지를 시간순으로 함께 비교해 현재 이용자를 먼저 표시. 퇴실 뒤에는 후속 일정을 표시 |
| 입실과 같은 초에 즉시 이동하면 출발지의 길이 0인 기록이 과거 캘린더와 충돌 검사에서 점유로 취급됨 | 이용 시간이 없는 구간은 점유·충돌에서 제외. 기록의 시작 시각이 같으면 종료 시각도 비교해 마지막 실제 자리를 표시 |
| 이동 완료를 누르지 않고 자동 퇴실하면 목적지가 실제 이용한 자리로 기록됨 | 만료된 이동 예약은 해제하고 실제 배정만 이용 이력으로 보존. 해제 사실은 변경 기록에 남김 |
| 날짜만 검사해 입실일 오후 2시 이전에도 입실 가능 | 확정된 공통 입실 시각인 14:00부터 허용. 현장 배정과 지정 객실 입실에 동일 적용하고 화면에도 안내 |
| 지난 백업 복원 직후에는 다음 자동 검사까지 이미 지난 입실·이동 상태가 남음 | 저장 작업 전후에 시간 경계를 반영해 복원·날짜 변경 직후에도 만료 상태를 정리 |
| 데이터 저장은 성공했지만 자동 백업에 실패한 경우, 창을 닫으면 경고가 사라짐 | 백업 경고를 일반 입력 오류와 분리해 유지. 초기 로드와 주기적 상태 확인에도 반영하고 백업 성공 후 해제 |
| 백업의 `99:99` 같은 잘못된 시각, 허용하지 않은 유형·상태, 이중 배정·기간 중첩이 검사를 통과 | 날짜·시각·선택값·참조·중복 배정·동일 자리 시간 중첩을 복원 전에 검사. 유효한 이동 예약의 출발지·목적지 확보는 허용 |
| 잠금 파일이 `null`이면 처음 설치한 것으로 오인하고, 구조가 잘못된 JSON이면 잠금 해제 단계에서 오류 발생 | 잠금 방식·salt·검증값 구조를 시작 시 검사. 손상된 파일은 덮어쓰지 않고 기존 오류 안내 경로로 처리 |
| 백업 폴더 설정을 디스크에 저장하지 못하면 실행 중 경로만 바뀜 | 설정 저장 실패 시 실행 중 경로도 이전 값으로 복구 |
| 한글 파일의 글자 수와 바이트 수 차이로 저장은 가능하지만 16MB 복원 제한에 걸릴 수 있음 | 저장 크기를 UTF-8 바이트로 검사하고 백업 내보내기는 저장본과 같은 간결한 JSON 형식 사용 |

폴더 열기·잠금 요청 실패도 화면에 표시하도록 보완했다. 복원 화면에서는 같은 파일을 다시 선택해 재시도할 수 있다. 디스크 저장 자체가 실패할 때는 기존 상태와 입력란을 보존하고 성공으로 알리지 않는 것도 확인했다.

## 검증 결과

- `npm test`: 운영 규칙·가져오기·파일 저장·손상 처리 **33개 통과**.
- `npm run test:ui`: 화면 회귀 테스트 **18개 통과**. 날짜·요일·검색·가져오기 등 기존 항목에 백업 실패 경고, 저장 실패 후 재시도, 잘못된 백업 거절, 지난 백업 복원, 11:00 퇴실 및 14:00 입실 경계를 추가했다.
- TypeScript 검사, 제품 빌드, 코드 형식 검사 통과. 빌드 중 Radix의 `use client` 지시문 경고는 있으나 빌드 실패는 없다.
- Mac에서 실제 **Electron 22 / Chromium 108** 실행기로 PIN·일반 비밀번호, 잘못된 PIN 거절, 잠금 중 데이터 접근 차단, XLSX 가져오기, 저장·재실행·첫 설치 복원, 백업 경로 실패와 복구, 손상된 원본 보존 후 복원을 확인했다. 테스트 전용 임시 폴더를 사용했다.
- [Windows 0.1.2 통합 설치 파일](../release/Sopung-Camp-Setup-0.1.2.exe)을 제작했다(137.8MiB). x64·ia32 실행 파일의 PE 형식, 내부 패키지 버전, 132개 소스·번들 파일이 최종 코드와 일치하는 것을 확인했다. [SHA-256](../release/Sopung-Camp-Setup-0.1.2.exe.sha256): `e881fc7cbcfd8f4adfca97079dc707b425abc109185e341e986f96101ffc1a4e`.

## 남은 한계

현재 환경은 Mac이다. Windows 8·8.1·10·11 실기기에서의 설치·업데이트·인쇄는 검증하지 못했다. 실제 캠핏·네이버 내보내기 파일과 현장 자리 자료도 아직 없어 공급자별 파일 검증·실제 운영 데이터 검증 완료로 표현하지 않는다.

레이트 종료 시각·금액, A동 전체 수 등 미확정 운영 값은 기존대로 비워 둔다. 자동 예약 연동을 추가하지 않았다. Windows 8 지원을 위해 고정한 Electron 22의 지원 종료와 개발용 설치 파일의 서명 여부는 [호환성 문서](windows-compatibility.md)에 기록한 상태 그대로다.

기존 기록에서 이미 실제 이용으로 저장된 미완료 이동은 출처를 확정할 수 없으므로 추정 삭제하지 않았다. 이번 수정은 이후의 자동 퇴실 및 아직 예정 상태인 이동 기록에 적용한다. 실제 파일에서 잘못된 과거 기록이 발견되면 해당 기록과 변경 이력을 함께 확인해야 한다.
