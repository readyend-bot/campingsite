# 소풍캠핑장 자리 배정 프로그램 — 요구사항 기록

작성일: 2026-09-28. 상태: **최신 사용자 지시로 구현 시작, 첫 동작 버전 제작**.
최신 결정 반영: 2026-11-06 · Q71–Q73. 0.1.15의 저장된 편집 배치를 유지하고, 0.1.16에 캠핏 로그인 후 자동 내려받기 흐름을 구현했다. 0.1.17에서 재시도 파일 분리·내보내기 출처 확인을 보강했다. 실제 캠핏 화면·파일과 Windows 검증은 남아 있다.

## 최신 제작 지시

사용자가 “이제 개발을 진행해볼까”, “코딩을 시작해보자”라고 명시했다. 이전의 코딩 대기를 해제하고 확정된 운영 규칙부터 구현한다. 전체 화면은 토스에서 영감을 받은 심플하고 깔끔한 디자인으로 구성하며 빈자리·배정·장박을 서로 다른 색과 글자로 구분한다. 구체적인 구현·검증 상태는 [구현 기준](implementation.md)과 [README](../README.md)를 따른다.

이후 사용자는 캘린더에서 요일을 잘못 읽지 않도록 더 눈에 띄게 표시하고, 전체 프로그램의 개선점을 재검토하라고 요청했다. 0.1.1에서 요일 확대·주말 구분·오늘 표시와 날짜 입력의 요일 안내를 적용하고 실제 사용 오류를 수정했다. [전체 재검토 기록](review-2026-09-28.md)을 참고한다.

추가 오류 재검토 요청에 따라 0.1.2에서 같은 날의 상태 표시, 연속 이동·자동 퇴실 이력, 14시 입실 경계, 백업·저장 실패와 손상 파일 검증을 보강했다. [두 번째 검토 기록](second-review-2026-09-28.md)에 결과와 미검증 범위를 기록했다.

2026-09-29 사용자가 오후 2시 이전 입실도 허용하라고 명시했다. 0.1.3부터 입실일 당일에는 현장 배정·지정 객실 모두 조기 입실을 허용한다. 기본 시각 14:00은 유지하되 강제 제한으로 사용하지 않는다. 실제 입실 시각부터 퇴실까지 전체 기간의 충돌을 검사한다.

2026-10-05에는 사용자 제공 도면 두 장의 사이트·시설·객실 종류를 적용했다. ‘장박’에 가려진 번호는 연번으로 복원하라는 명시적 지시를 따르며 장박 점유 기록은 생성하지 않는다. 전체 배치에서 동을 클릭해 상세 화면에서 자리를 선택하고 다시 전체 배치로 돌아갈 수 있다. 현재 예약 경로는 캠핏만이며 로그인은 Windows 설치 후 사용자가 진행한다. [도면 반영 기록](site-plan-2026-10-05.md).

2026-10-08 전체 프로그램 재검토 요청에 따라 0.1.12에서 복원·가져오기·배정 데이터 검증·백업 재시도 오류를 수정했다. 도면·운영 규칙과 Windows 8 이상 지원 목표는 유지한다. [최종 재검토 결과](final-review-2026-10-08.md)에 통과한 검사와 실제 Windows·캠핏·보안 관련 남은 확인 사항을 기록했다.

같은 날 Claude 독립 검토([검토 보고서](claude-final-review-2026-10-08.md))의 확정 오류를 0.1.13에서 고쳤다. 사용자는 저장 용량 문제에 대해 지난 연도 기록을 보관 파일로 분리하고 과거 검색을 유지하는 방식을 선택했다(Q70). 현재 연도에 끝난 기록의 수동 보관 허용 여부는 확인 중이며, 답변 전에는 지난 연도만 보관한다.

2026-10-10 사용자가 Windows 설치 후 자리가 비어 있고 캠핏 로그인·엑셀 내려받기 후 완료하지 못했다고 보고했다. 신규 저장 파일에 기본 도면을 등록하지 않던 흐름을 수정해 0.1.14부터 저장 파일 없는 신규 설치만 확정 140자리·15시설을 자동 준비한다. 기존 운영 파일·편집은 유지한다. 캠핏 일반 내보내기 링크 인식·실패 단계 안내를 보강했으며 사용자 환경의 정확한 실패 지점은 파일 형식·열·오류 확인이 필요하다. [조사 결과](windows-install-investigation-2026-10-10.md)와 [요청한 매뉴얼](camfit-sync-2026-10-06.md)을 따른다. 로그인 요청을 반복하지 않는다.

## 목적과 사용 흐름

캠핑장 사장님이 예약 사이트에서 내려받은 명단을 프로그램에 불러오고, 현장 체크인 순서에 따라 실제 자리를 지정·수정·관리한다. 오토캠핑과 글램핑의 예약 슬롯 번호를 현장의 자리 번호로 오인하지 않아야 한다.

기본 흐름은 `예약 명단 불러오기 → 예약자 검색 → 숙박 기간에 맞는 빈자리 확인 → 배정·입실 → 필요 시 자리 이동 → 퇴실`이다. 1박·연박을 다루는 캘린더와 과거 기록 검색이 필요하다.

장박 사이트에는 해당 기간에 일반 손님을 배정할 수 없다. 캠핑장 각 동은 계단식으로 구성되며 일부 동에는 글램핑·카라반·방갈로가 함께 있다.

### 선택의 적용 범위

- Q71은 0.1.15에 반영한다. `src/bundledLayout.json`은 현재 Mac 파일에서 자리·시설만 추출한 고정본이며 신규 PC에만 자동 적용한다. 기존 PC는 설정의 ‘저장된 자리배치 적용’에서 백업 후 위치·크기를 맞추며 기존 ID·예약·배정·장박·삭제 상태·항공사진을 유지한다. 원본에는 항공사진이 없다. [배치 포함 기록](bundled-layout-2026-11-06.md).
- Q72·Q73의 [자동 연결 설계](camfit-auto-connect-2026-11-06.md)를 이어서 진행하라는 사용자 요청에 따라 0.1.16에 단일 연결 흐름을 구현했다. 수신 준비 후 로그인 창을 열고 인식 가능한 예약 메뉴·유일한 내보내기를 자동 조작한다. 첫 파일의 열·상품·상태는 사용자가 확인하며 같은 형식은 다음부터 자동 반영한다. 단계 표시·재로그인 후 경로 복귀·재시도·중단을 포함한다. 모의 화면·XLSX 검증과 실제 공급자 검증은 구분한다. 업체·조회 범위·실제 DOM·실제 파일 형식 맞춤은 확인 대기다. 비밀번호·즉시 로그인을 다시 요구하지 않는다. [구현과 한계](camfit-connection-2026-11-06.md).

- 초기의 “PC나 태블릿” 구상은 이후 Q4·Q5·Q24에서 윈도우 PC 한 대와 설치형으로 구체화되었다. 태블릿·클라우드·실시간 동기화를 기본 범위에 추가하지 않는다.
- Q27은 오토캠핑 손님을 **오토캠핑 자리**에 배정하는 규칙이다. 글램핑이나 카라반으로 임의 전환하는 권한을 의미하지 않는다.
- Q23은 취소, Q29는 숙박 날짜 변경에 대한 결정이다. 둘 다 사장님 확인 후 반영한다. 상품·인원 등 다른 필드 변경의 갱신 방식은 아직 정하지 않았다.
- Q25의 같은 PC 내 백업은 PC나 디스크 자체가 고장 나는 경우에 대비한 외부 백업이 아니다. 이전 대화에서 설명한 한계이며, 다른 백업 방식을 사용자 결정 없이 도입하지 않는다.
- Q22는 별도 배정 관리를 뜻한다. 원래 예약번호와 연결을 지워도 된다는 뜻은 아니다. 반복 가져오기에서 다중 자리 건을 구별하는 기준은 실제 명단을 보고 정한다.
- Q30은 당일 자리 상태의 자동 전환에 관한 결정이다. 연박 중간 날짜에는 적용하지 않으며, 과거 예약·배정 이력은 Q17대로 보존한다. Q31·Q32에 따라 모든 숙박 유형의 기본 퇴실 시각은 오전 11시다. Q33·Q34에 따라 유료 레이트 체크아웃을 적용한 예약에는 공통 레이트 종료 시각을 적용하고 그 시각에 자동 전환한다. 레이트 종료 시각의 실제 값은 사용자가 나중에 알려주기로 했으므로 임의로 정하지 않는다. Q35에 따라 설정한 추가요금을 자동 입력하되 수정할 수 있다. 구체적인 요금은 아직 미정이다.
- Q35의 금액 자동 입력과 Q8의 결제 여부 기록은 별개다. 금액을 채웠다는 이유만으로 결제 완료로 처리하지 않는다.
- Q36에 따라 당일 다음 입실이 있다는 이유만으로 레이트 체크아웃을 막지 않는다. 같은 자리의 이용 시간이 실제로 겹치는지 확인해야 한다.
- Q37은 기본 입실 시각에 대한 결정이다. Q48의 최신 지시에 따라 입실일 당일에는 14:00 이전에도 사장님이 입실 처리할 수 있다. 기존 손님·장박·사용중지와 실제 이용 시간이 겹치면 차단하며, 입실일 전날까지 허용 범위를 넓히지 않는다. 오후 2시가 되었다고 자동 입실 처리하지 않는다.
- Q38은 현장에 도착한 손님의 수동 자리 배정에 적용한다. Q15의 명단 불러오기 시 카라반·방갈로 지정 객실 자동 배치는 도착·입실 처리와 구분한다.
- Q39의 미래 이동 예약을 등록했다고 현재 손님의 위치가 즉시 바뀌지는 않는다. 이동할 자리의 해당 이용 기간은 다른 배정·장박·사용중지와 겹치지 않아야 한다. Q40에 따라 예정일에는 이동 예정으로 표시하고 사장님이 이동 완료를 눌러야 실제 자리 상태를 전환한다. 확인 전 출발지를 자동으로 빈자리로 바꾸지 않는다. 이동 예정지의 기간 확보와 실제 점유 표시는 구분한다.
- Q41에 따라 이동 대상은 해당 이용 기간에 비어 있는 자리다. 두 손님의 배정을 한 번에 맞바꾸는 동작은 제공하지 않는다. 미래 이동의 가능 여부는 현재의 빈자리 여부만이 아니라 이동할 기간 전체를 기준으로 판단한다.
- Q42의 현장 연장은 프로그램 내 숙박·배정 기록 변경이다. 연장할 기간에도 다른 예약·장박·사용중지와 겹치지 않아야 한다. 명단을 다시 불러왔다고 현장에서 연장한 퇴실일을 자동으로 되돌리지 않는다. 외부 원본의 날짜 변경은 Q29의 확인 절차를 적용하며, 외부 예약 사이트 자동 변경·동기화는 포함하지 않는다.
- Q43의 조기 퇴실은 사장님이 직접 처리한다. 해당 손님의 남은 자리 배정을 해제하되 원래 예약 정보와 실제 퇴실 시점·배정 이력은 보존한다. 다른 손님의 배정이나 장박·사용중지까지 해제하지 않는다. 환불이나 외부 예약 취소는 이 결정에 포함되지 않는다.
- Q44의 노쇼는 사장님이 직접 확정한다. 입실 가능 시각이 지났다는 이유만으로 자동 노쇼 처리하지 않는다. 해당 예약의 자리 배정을 해제하고 노쇼 기록·이력을 보존하며, 명단 재불러오기로 노쇼 상태나 해제한 배정을 자동으로 되돌리지 않는다.
- Q45는 실제 관리실 PC의 버전을 답한 것이 아니라 제품의 최소 지원 범위를 정한 것이다. 현재는 Electron 22.3.27로 첫 버전을 구현했다. Windows별 실제 설치·실행은 남아 있으며 [호환성 검토](windows-compatibility.md)에 근거·한계·검증 항목을 기록했다.
- Q49의 배치 수정은 화면에 표시하는 사이트 위치를 바꾸는 기능이다. 손님의 배정 자리를 다른 사이트로 옮기는 동작과 구분하며, 예약·장박·사용중지 기록을 유지한다. 동별 배치와 전체 항공사진 위치는 따로 저장한다. [0.1.4 사용 방법과 검증](area-layout-2026-09-29.md)을 참고한다.
- Q70은 0.1.13에 적용했다. 보관 대상은 올해(한국 시간) 이전에 끝난 퇴실·노쇼·취소 예약과 그 배정·변경 기록, 예약과 무관한 지난 연도 기록이다. 도착 전(미처리 포함)·입실·이동 예정 예약, 확인 전 원본 변경, 장박·사용중지, 자리·시설·설정은 본 파일에 남긴다. 보관은 설정 화면에서 사장님이 실행하며 자동 실행은 정하지 않았다. 반복 가져오기는 보관된 예약을 새로 만들지 않는다. 자동·수동 백업과 복원은 보관 파일을 함께 다루고, 예전 단일 백업 복원도 유지한다. 현재 연도에 끝난 기록의 수동 보관은 사용자 답변 전이라 허용하지 않는다.
- Q69는 0.1.11에 적용했다. 트램펄린은 도로가 꺾이는 모서리 바로 위에 표시한다. 이전 기본 위치만 한 번 갱신하며 이후 사용자가 다시 옮긴 위치는 재실행에서도 유지한다.
- Q68은 0.1.10에 적용했다. 0.1.9 기본 위치였던 트램펄린만 길 위로 정정하며 직접 편집한 시설 위치는 유지한다.
- Q65·Q66은 0.1.9에 적용했다. 시설은 15개이며 기존 라동 위치의 간격을 유지해 오른쪽 여백만 늘린다. 자동 갱신은 전체 도면 초기화가 아니며 다른 동·예약·배정·장박·항공사진 좌표를 보존한다. [추가 시설과 단차](site-additions-2026-10-06.md).
- Q51은 직접 제공한 도면의 번호 복원을 허용한 최신 지시다. 출처 없는 자리나 무번호 추가 칸을 만드는 허용이 아니다. 도면의 140자리와 14시설을 적용하되 기존 등록 자리 ID·예약·배정·장박 기록을 보존한다. 방갈로 A/B는 도면 명칭을 유지하고 오토 사이트 번호로 바꾸지 않는다.
- Q50 이후에도 예전 예약 경로 기록을 삭제하지 않는다. 신규 직접 입력의 기본 경로는 캠핏이다. Q52의 로그인 창은 예약 자동 수신 완료를 뜻하지 않으며, 실제 조회 규격을 확인한 후 수신 기능을 연결한다.

## 개발 후 확인할 항목

Q46의 잠금 방식 선택은 답변을 받기 전에 사용자가 개발 시작을 요청했다. 설치 앱의 첫 실행 화면에서 숫자 6자리 PIN 또는 일반 비밀번호를 선택할 수 있게 구현한다.

잠금 필요 여부는 Q19에서 확정되어 있다. PIN·비밀번호 원문을 대화나 예약 백업에 넣지 않는다. 비밀번호 분실 복구 정책은 아직 미확정이다.

Q28의 A동 개수 확인 대기는 Q51의 직접 제공 자료와 연번 복원 지시로 갱신했다. A1–A26을 반영하며 같은 질문을 반복하지 않는다.

Q34의 레이트 공통 종료 시각은 사용자가 확인 후 나중에 전달하기로 했다. 다시 묻거나 임의의 시간으로 확정하지 않는다.

0.1.8에는 로그인 세션을 이용하는 **CSV/XLSX 내보내기 기반 버튼 동기화**를 구현했다. 처음에는 캠핏 창에서 실제 내보내기를 누르고 예약번호·날짜·상품·상태 열을 확인한다. 확인한 화면 경로·내보내기 버튼·열 연결을 저장하고 다음 동기화에서 파일을 자동 수신해 기존 가져오기 규칙으로 반영한다. API 주소를 추정하거나 로그인 여부를 예약 수신 성공으로 처리하지 않는다. 실제 캠핏의 내보내기 기능과 파일 규격은 Q64대로 확인 전이다. 실제 계정 인증·자동 내보내기 검증은 Windows 첫 연결에서 진행한다. 주기 자동 실행·지정 폴더 감시는 구현하지 않았다. [연결 안내와 검증 범위](camfit-sync-2026-10-06.md).

## 남은 확인 항목

아래는 인터뷰 순서를 위한 내부 목록이다. 사용자에게 한꺼번에 묻지 않는다. 확인이 끝난 항목은 결정 기록으로 옮긴다.

### 현장 구성

- 도면 반영 이후 달라진 현장 배치는 운영자가 편집한다. 도면의 무번호 추가 칸은 등록하지 않았으며 향후 실제 자리라고 확인되는 경우에만 추가한다.
- 장박 목록·기간과 사용중지 자리는 사용자가 직접 등록한다. 사진의 장박은 초기 점유 데이터가 아니다.
- 글램핑의 동 제한·상품과 물리 자리 연결 규칙은 실제 캠핏 명단으로 확인한다. 라1–11의 글램핑 위치는 Q51로 반영했다.

### 명단 가져오기와 변경

- 캠핏 내보내기 종류와 실제 파일의 열·날짜·예약번호·다중 자리 표현.
- 현재 수신 대상은 캠핏만이다. 기존 예약 경로 이력은 보존하며 서로 다른 경로의 과거 기록을 이름·연락처만으로 합치지 않는다.
- 자체 프로그램에서 사용할 수 있는 공식 예약 조회 API 또는 자동 내보내기 제공 여부와 이용 조건. 지정 폴더 자동 가져오기는 파일 다운로드까지 자동화하는 기능과 구분한다.
- 예약번호가 없거나 다중 자리 예약을 구별하기 어려운 행의 처리.
- 이미 배정한 예약의 상품·인원 변경을 가져올 때의 처리. 날짜 변경은 Q29에서 사장님 확인 후 반영으로 결정함.
- 파일에서 사라진 예약과 명시적으로 취소된 예약의 구분.
- 같은 날짜 중복 행, 부분 기간 파일, 읽을 수 없는 행을 처리하는 방식.

### 입퇴실·이동·편집

- 기본 시각은 입실 오후 2시(Q37), 퇴실 오전 11시(Q31·Q32)로 전체 공통 결정함. Q38에 따라 도착한 손님의 현장 자리 배정과 입실 처리는 한 번에 수행함.
- 퇴실 시각 자동 빈자리 전환은 Q30, 유료 레이트 체크아웃 예외는 Q33에서 결정함. 레이트 종료 시각은 Q34에서 공통 적용으로 결정했고 실제 값은 사용자 확인 대기. 레이트 요금은 Q35에서 설정 금액 자동 입력·수정 가능으로 결정함. Q36에 따라 당일 다음 손님이 있어도 시간이 겹치지 않으면 레이트를 허용함. Q42에 따라 현장 숙박 연장은 직접 퇴실일을 늘리고 추가요금을 기록함. 실제 추가요금 금액과 별도 정비 차단 필요 여부는 미정.
- Q39에서 즉시 이동과 날짜를 정한 이동 예약을 모두 지원하기로 결정함. Q40에 따라 예정된 이동은 사장님이 이동 완료를 눌러 실제 자리 상태를 전환함. Q41에 따라 빈자리로 이동만 지원하고 맞교환 기능은 제외함. 이동 전후의 배정 이력은 Q17의 과거 기록 요구에 따라 보존함.
- Q43에 따라 조기 퇴실은 사장님이 처리하면 즉시 자리 해제. Q44에 따라 노쇼도 사장님이 확정하면 해당 예약의 배정 자리를 해제함.
- 기존 예약과 장박 기간이 충돌할 때 처리.
- 사용 이력이 있는 자리의 삭제·번호 변경 방식.
- 레이트 추가요금의 실제 설정 금액과, 그 밖의 추가요금을 수동으로 기록할지 규칙에 따라 계산할지.

### 설치·보관·복구·화면

- Q45에 따라 윈도우 8 이상을 지원 목표로 함. 실제 PC의 세부 환경과 화면 크기는 설치 검증에 맞춰 확인. 런타임·의존성·설치 파일 검토는 [호환성 검토](windows-compatibility.md)를 따름.
- 잠금 입력 방식(Q46)과 분실 시 복구 방식.
- 백업 경로·보관 기간·복구 절차와 프로그램 종료 상태에서의 백업 처리. 지난 연도 기록 분리는 Q70으로 정했지만 일일 백업 파일의 보관 기간과 현재 연도 완료 기록의 수동 보관 허용 여부는 확인 중이다.
- 캘린더 기본 단위, 인쇄 용지·표시 정보.
- 현장 자료를 반영한 화면 설계와 최종 제작 계획.

## 설계 검토 시 지킬 점

아래는 현재 구현과 후속 변경에서 지킬 기술적 원칙이다. 현재 데이터 모델은 `src/domain.ts`, 실행 구성은 [구현 기준](implementation.md)을 따른다.

- 예약 원본, 실제 손님 입퇴실 상태, 자리 배정 이력은 서로 다른 정보다. 취소 알림을 수신했다고 현재 배정을 자동으로 지우면 Q23을 위반한다.
- 현장 자리와 온라인 판매 슬롯은 별개로 식별한다. 캠핏의 `선착순01`을 `가1` 등으로 자동 해석하지 않는다.
- 중복 없이 다시 불러오되, 이름·전화·날짜가 비슷하다는 이유만으로 서로 다른 예약을 자동 합치지 않는다.
- 날짜 전체의 겹침을 검사해야 한다. 첫날만 비어 있는 자리를 연박 손님에게 배정하면 안 된다.
- 반복 가져오기로 현장 메모·차량번호·배정 이력이 의도치 않게 사라지지 않도록 필드별 갱신 원칙을 마련한다.
- 자동 퇴실은 해당 손님의 점유 종료를 반영한다. 같은 자리의 다른 유효한 배정·장박·사용중지를 공실로 덮어쓰지 않는다.
