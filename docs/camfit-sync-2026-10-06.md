# 캠핏 예약 동기화

최초 작성: 2026-10-06 · 0.1.8. 사용 순서 갱신: 2026-10-10 · 0.1.14.

2026-10-10 사용자가 Windows 설치·캠핏 로그인·엑셀 내려받기를 했지만 완료하지 못했다고 알려 주었다. 실제 오류 문구·파일 형식·열은 아직 확인하지 못했다. 아래는 소풍 앱의 실제 버튼·필드에 맞춘 사용 순서이며, 확인하지 못한 캠핏 내부 메뉴 이름은 지정하지 않는다.

## 지금 Windows에서 자리 표시하기

1. 소풍캠핑장 앱의 **자리 배정** 화면으로 이동한다.
2. 자리가 비어 있으면 상단의 **소풍캠핑장 도면 적용**을 누른다. 확정 도면의 7개 동·140자리·15시설을 등록한다. 장박은 직접 등록한다.
3. 개발 Mac에서 바꾼 자리 위치·항공사진까지 옮기려면 Mac의 **설정 → 백업 파일 내보내기**로 만든 백업 폴더 전체를 Windows로 복사한 뒤 **설정 → 백업 폴더에서 복원**으로 그 폴더의 JSON을 선택한다.

0.1.14부터 저장 파일이 없는 신규 설치는 기본 도면을 자동 생성·저장한다. 이미 저장한 빈 상태·편집 위치·기존 기록은 자동으로 교체하지 않는다.

## 첫 동기화의 정확한 순서

**먼저 소풍 앱에서 동기화를 시작한 뒤, 대기 중인 앱의 캠핏 창에서 내려받아야 한다.** 일반 Chrome에서 받거나 동기화 시작 전에 받은 파일은 자동으로 수신하지 않는다.

1. **설정 → 캠핏 동기화**를 누른다. 이미 캠핏에 로그인했다면 그대로 사용한다.
2. 소풍 앱에 **캠핏 명단을 기다리고 있어요**가 표시되면 **캠핏 창 보기**로 앱이 연 캠핏 창을 확인한다.
3. 해당 캠핏 창에서 원하는 예약 조회 기간·조건을 확인하고 실제 **엑셀 내려받기/다운로드** 조작을 한다. 대기는 3분이다. 이미 시간 초과가 났다면 닫고 1번부터 다시 진행한다.
4. 소풍 앱으로 돌아온다. 파일 이름과 예약 행 수, 열 연결 화면이 나와야 파일을 받은 것이다. 캠핏에서 내려받기를 눌렀다는 것만으로 소풍 앱 저장이 끝난 것은 아니다.
5. **캠핏 내보내기 버튼**에서 방금 사용한 실제 내보내기 항목을 선택한다. 항목이 비어 있으면 이 방식의 첫 연결을 완료할 수 없다. 0.1.14는 일반 다운로드 링크도 인식하도록 보강했지만 실제 캠핏 컨트롤과의 일치는 확인이 필요하다.
6. 별표가 붙은 다음 항목을 파일의 해당 열과 연결한다. 각 항목에는 서로 다른 열을 선택한다.

| 앱 항목 | 선택할 파일 열의 내용 |
|---|---|
| 예약번호 * | 예약을 고유하게 구분하는 번호 |
| 예약자 이름 * | 손님 이름 |
| 입실일 * | 연도를 포함한 입실 날짜 |
| 퇴실일 * | 연도를 포함한 퇴실 날짜 |
| 숙박 유형 * | 예약 상품 또는 숙박 유형 |
| 예약 상태 * | 예약·취소 등 실제 원본 상태 |

연락처·인원은 해당 열이 있으면 연결한다. 같은 예약번호로 여러 자리 예약이 반복되면 원본의 안정적인 **단위번호** 열도 연결해야 한다. 날짜는 `2026-10-10`처럼 연도가 있어야 한다. 카라반·방갈로의 **지정 객실**은 실제 객실 이름과 맞을 때 연결한다. 오토·글램핑의 온라인 선착순 번호를 실제 자리번호로 연결하지 않는다.

7. **캠핏 상품의 숙박 유형**에서 각 상품을 **오토캠핑·글램핑·카라반·방갈로** 중 실제 유형에 연결한다.
8. **캠핏의 예약 상태**에서 확정 예약은 **예약으로 가져오기**, 확정 취소는 **취소로 가져오기**로 선택한다. 의미를 모르는 상태는 예약으로 추정하지 않고 확인한다. **가져오지 않기**를 고른 행은 이번 명단에서 제외된다.
9. **동기화 미리보기**의 이름·날짜·유형·상태와 오류 안내를 확인한다. 오류가 없어야 **연결하고 동기화**를 누를 수 있다.
10. **예약 목록을 동기화했어요**와 신규·변경 확인·동일 건수가 나오면 **완료**를 누른다. 설정의 **연결 설정됨**과 **마지막 동기화** 시각도 확인한다.

이후 같은 예약 화면·파일 형식은 **캠핏 동기화** 버튼으로 받는다. 화면이나 형식이 바뀌면 열·상품·상태를 다시 확인할 수 있다. 취소·날짜 변경은 **예약 명단**에서 확인 후 반영하며 기존 자리 배정은 그때까지 유지한다.

## 이미 내려받은 파일을 직접 넣기

1. 동기화 대기 창을 닫고 **예약 명단 → 명단 가져오기**를 누른다.
2. **예약 경로**를 **캠핏**으로 두고 **명단 파일을 선택해 주세요**에서 받은 파일을 선택한다.
3. **예약번호·예약자 이름·입실일·퇴실일·숙박 유형**을 연결하고, 파일에 **예약 상태**가 있으면 반드시 해당 열도 연결한다. 상태를 연결하지 않으면 취소 행까지 예약으로 가져올 수 있다.
4. 수동 가져오기는 상품별 유형·상태 연결 화면이 없다. 파일 값이 **오토캠핑·글램핑·카라반·방갈로**, 상태는 **예약·예약 완료·취소·취소 완료**여야 한다. 다른 상품명/상태면 원본은 보관하고 복사본에 실제 의미에 맞는 유형·상태 열을 추가해 그 열을 연결한다. 의미를 모르는 값은 임의로 바꾸지 않는다.
5. 미리보기와 오류를 확인하고 **N건 가져오기 → 완료**를 누른다. 이 방법은 예약을 가져오지만 자동 동기화 연결 설정은 만들지 않는다.

파일은 **XLSX 또는 UTF-8 CSV, 8MB 이하**여야 한다. XLSX는 **첫 번째 시트**를 읽는다. `.xls` 파일은 Excel에서 열고 **다른 이름으로 저장 → Excel 통합 문서(.xlsx)**로 새 파일을 만든 뒤 선택한다. 확장자만 바꾸는 것은 변환이 아니다.

## 완료하지 못할 때

| 보이는 상황 | 확인할 것 |
|---|---|
| 내려받았는데 앱은 계속 기다림 | 앱의 동기화가 대기 중이었는지, 일반 Chrome이 아니라 앱의 캠핏 창에서 받았는지 확인. 이미 받은 파일은 수동 가져오기 사용 |
| CSV 또는 XLSX 안내 | 파일이 `.xls`인지 확인하고 실제 XLSX로 변환 |
| 내보내기 버튼 목록이 비어 있음 | 컨트롤 인식 단계 문제. 0.1.14의 일반 링크 인식 수정으로 재확인하거나 수동 가져오기 사용 |
| 연결하고 동기화가 비활성 | 내보내기 항목 선택, 필수 열, 상품 유형·상태, 미리보기 오류 확인 |
| 날짜·예약번호·단위번호 오류 | 연도 포함 날짜, 원본 예약번호, 여러 자리 예약 식별 열 확인 |
| 명단 저장 실패 | 화면 오류와 설정의 저장 용량·파일 경로를 확인. 파일 수신과 앱 저장은 별도 단계 |

같은 문제를 재현하면 **소풍 앱에 표시된 오류 문구**를 그대로 확인한다. 오류가 불명확한 현재 보고만으로 파일 형식·열·컨트롤·저장 중 어느 단계인지 확정하지 않는다.

사용자가 ‘한 번 로그인한 뒤 동기화 버튼으로 예약 목록을 받기’를 요청했다(Q61). 계정이나 비밀번호를 요청하지 않는다(Q52). Q64 당시에는 내보내기 확인 전이었으며, 2026-10-10 사용자가 엑셀 내려받기까지 했다고 보고했다. 실제 파일 형식·열·앱 수신 여부는 확인 중이다.

## 첫 연결

1. 설치 앱에서 **설정 → 캠핏 로그인**으로 공식 [캠지기센터](https://admin.camfit.co.kr/)에 직접 로그인한다.
2. **캠핏 동기화**를 누른다. 열린 캠핏 창에서 원하는 예약 목록·조회 조건을 선택하고 **CSV 또는 XLSX 내보내기**를 누른다. 자동 다운로드가 없으면 명단을 기다리는 동안 캠핏 창에서 직접 진행할 수 있다.
3. 프로그램으로 돌아와 예약번호·입퇴실 날짜·이름·숙박 유형·예약 상태 열을 확인한다. 온라인 상품 이름은 숙박 유형에 연결하고 확인하지 못한 상태는 처리 방법을 직접 정한다. 여러 자리 예약은 안정적인 단위번호가 필요하다.
4. 미리보기를 확인하고 **연결하고 동기화**를 누른다. 내보내기 화면·버튼·열 연결을 PC에 저장한다.
5. 다음부터 **캠핏 동기화**를 누르면 같은 화면을 열고 확인한 내보내기 버튼을 찾아 명단을 받는다. 저장 후 신규·변경 확인·동일 건수와 마지막 동기화 시각을 표시한다.

조회 조건에 포함된 예약만 받는다. 저장한 화면을 다시 열었을 때의 실제 조건은 캠핏 화면에서 확인한다. URL의 필터 쿼리를 저장하지 않는다. 버튼이 안 보이거나 중복으로 보이면 자동 클릭하지 않고 사용자가 캠핏 창에서 내보내기를 누를 수 있다. 로그인 만료·보안 확인도 해당 창에서 직접 처리한다. 열 구성이 바뀌거나 새로운 상품·상태가 있으면 자동 반영을 멈추고 연결 화면을 다시 표시한다.

캠핏에 내보내기가 없거나 파일이 XLS, 연도 없는 일일표, 예약번호 없는 명단이면 현재 방식으로 바로 연결할 수 없다. API 주소·응답을 추정하지 않았으며 실제 화면에서 추가 연결이 필요한 경우 그 자료를 기준으로 수정한다. 수동 CSV/XLSX **명단 가져오기**는 별도로 유지한다.

## 예약 보존 규칙

- 캠핏 예약번호와 단위번호로 중복을 구별한다. 같은 파일을 다시 받아도 기존 예약을 추가로 만들지 않는다.
- 취소와 숙박 날짜 변경은 기존 확인 목록에 보류한다. 확인 전 배정·원래 날짜는 유지한다.
- 조회 목록에서 사라졌다는 이유로 예약을 취소하거나 삭제하지 않는다.
- 현장 메모·차량·요금·연장·노쇼 이력을 유지한다. 상품·인원·이름 등 변경은 기존 알림 규칙을 따른다.
- 온라인 선착순 번호를 가1 등 실제 사이트 번호로 변환하지 않는다. 카라반·방갈로의 지정 객실은 실제 등록 이름과 정확히 일치할 때 기존 규칙대로 배정한다.
- 필수 열 누락, 단위 중복, 날짜·인원 오류, 파일 손상, 다운로드 실패는 전체 저장 전에 차단한다. 이전 명단을 대신 가져오지 않는다.

## 저장과 접근

로그인은 별도 영속 브라우저 세션을 사용한다. 로그인 원문·쿠키·인증 토큰을 읽거나 예약 JSON에 넣지 않는다. 공급자가 세션을 만료시키면 다시 로그인이 필요하다. `camfit-sync.json`에는 예약 화면 경로·내보내기 버튼·열·상품/상태 연결·마지막 동기화 시각만 저장한다. 이 연결 설정과 브라우저 세션은 예약 백업에 포함되지 않으므로 새 PC 복원 뒤 처음 연결을 다시 진행한다.

앱의 동기화 요청 중 해당 캠핏 창이 만든 파일만 받는다. 한 번에 CSV/XLSX 8MB·5,000행·100열까지 처리하며 임시 파일은 처리 후 삭제한다. 다른 창이나 일반 다운로드는 가로채지 않는다. 취소·창 닫기·앱 잠금·시간 초과에서는 성공으로 처리하지 않는다. 캠핏 창에는 예약 파일 IPC나 Node 접근을 제공하지 않는다.

## 확인한 범위와 남은 검증

- 운영 테스트 49개 통과. 새 상품·미확인 상태·열 변경·연도 누락·단위 중복 차단, 취소/변경 시 배정 보존, 누락 예약 유지, 다운로드 출처 제한·임시 파일 삭제·시간 초과·설정 검증을 포함한다.
- Mac Electron 22 / Chromium 108에서 **실제 DownloadItem과 IPC**를 통해 CSV를 받고, 처음 열 연결 뒤 버튼 동기화·반복 수신·지정 카라반 배정·날짜/취소 보류·XLS 거절 시 원본 보존을 확인했다. 공식 도메인에 로컬 모의 화면을 반환하는 테스트이며 실제 계정이나 운영 예약을 사용하지 않았다.
- 실제 캠핏 로그인·화면 경로·내보내기 버튼·CSV/XLSX 열·다중 자리 표현·조회 범위는 **미검증**이다. 공개 로그인 접근에서는 보안 확인 화면만 보였으며 이를 우회하지 않았다. [공식 사업자 안내](https://biz.camfit.co.kr/)는 예약 관리 기능을 소개하지만 이 프로그램용 API나 실제 내보내기 규격은 확인하지 못했다.
- Windows 8·8.1·10·11의 실제 설치·로그인·동기화는 해당 PC에서 확인해야 한다. 설치 파일 생성과 실기기 검증은 구분한다.
