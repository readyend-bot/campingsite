# 전체 프로그램 최종 재검토

검토일: 2026-10-08. 수정 버전: **0.1.12**.

예약 등록·검색·명단 가져오기, 자리 배정·입퇴실·이동·연장, 장박·사용중지, 도면·캘린더·인쇄, 저장·백업·복원·잠금, 캠핏 파일 수신과 설치 파일 구성을 재검토했다. 아래 기능 오류를 수정했고 운영 규칙 테스트 60개, 화면 테스트 38개, Mac Electron 22 실행 검증과 Windows 설치 파일 빌드를 통과했다. 실제 Windows 설치·실행과 실제 캠핏 계정의 내보내기는 아직 검증하지 않았다.

테스트는 별도 임시 폴더와 브라우저 테스트 환경에서 진행했다. 이번 검토에서 사용자의 운영 데이터·자리 편집·PIN을 변경하지 않았다.

## 발견한 오류와 수정

| 중요도 | 오류를 일으키는 경우 | 수정 결과 |
|---|---|---|
| 중요 | 시설·도면 정보가 없는 예전 백업을 설정 화면에서 복원하면 현재 시설·도면 식별자가 남음 | 전체 상태를 검증한 복사본으로 교체하고 백업에 없는 선택 필드도 제거한다. 원본 백업의 객체를 공유하지 않는다. |
| 중요 | 이전 도면의 백업을 복원하면 재실행 전까지 예전 시설 위치가 표시됨 | 복원 직후 `upgradeSopungPlan`을 실행한다. 기존 편집 위치·항공사진 좌표·예약·배정은 유지하며 이전 기본 시설 위치만 갱신한다. |
| 중요 | 체험에서 실제 운영으로 전환하거나 예시를 다시 만들 때 이전 시설·도면 정보가 잔존 | 빈 운영 상태·예시 상태·최초 도면 상태로 전환하는 경로에 동일한 전체 교체 처리를 적용했다. |
| 중요 | 수동 명단의 `취소 완료`를 일반 예약으로 가져오거나 알 수 없는 상태를 예약으로 추정 | 공백을 정리해 취소를 판별한다. 상태 열이 연결된 경우 미확인 값·빈 값은 오류로 표시하고 저장을 막는다. 상태 열을 연결하지 않은 경우 모두 일반 예약으로 읽는 기존 동작은 화면에 설명했다. |
| 중요 | 필수·선택 열을 같은 열에 연결하거나 범위 밖 열을 지정 | 수동 가져오기·캠핏 미리보기·캠핏 연결 설정 저장에서 모든 연결 열의 중복과 범위를 검사한다. |
| 보통 | 100열이 넘는 CSV 또는 UTF-8이 아닌 파일을 읽으면 과도한 열이나 깨진 이름이 들어옴 | CSV에도 100열 제한을 적용하고 잘못된 UTF-8을 거절한다. UTF-8 CSV 또는 XLSX로 저장하도록 안내한다. |
| 중요 | 손상된 백업에 종료 예약의 현재 배정, 입실 손님의 배정 누락, 숙박 유형 불일치, 입실 전 이동 예약, 한 예약의 실제 이용 시간 중복이 있음 | 상태 간 관계를 검증해 저장·복원 전에 거절한다. 정상 이동 계획의 출발지 유지와 목적지 확보는 허용한다. |
| 보통 | 자동 백업 파일 생성 후 백업 날짜 설정 기록만 실패 | 다음 검사에서 파일이 이미 있어도 날짜 기록을 재시도한다. 설정 기록 실패 시 메모리 설정을 원래 값으로 돌리고 성공 후 경고를 해제한다. |

관련 변경은 `src/domain.ts`, `src/App.tsx`, `src/importer.ts`, `src/camfitSync.ts`, `src/forms.tsx`, `electron/camfit-sync.cjs`, `electron/repository.cjs`에 적용했다. 새 회귀 테스트는 `tests/finalReview.test.ts` 7개와 `tests/ui/finalReview.spec.ts` 4개다.

전체 도면 화면도 확인했다. 7개 동·140자리·15시설, 마동 위치, 두 계단 연결, 도로 모서리 위 트램펄린, 마7·마8의 얇은 단차 선을 유지한다. 동을 오가도 손님·날짜를 유지하고 당일 오전 입실을 허용하는 기존 규칙을 변경하지 않았다.

빌드 중 Radix의 `use client` 지시문과 electron-builder의 중복 의존성 참조 안내가 출력됐으나 빌드는 성공했다. 현재 클라이언트 전용 앱의 동작은 화면 테스트와 실제 Electron 실행기로 확인했다.

## 보안 검사와 남은 개선사항

`http-cache-semantics`를 4.2.0 → 4.3.0, `source-map-js`를 1.2.1 → 1.2.2로 갱신했다. 그 외 직접 의존성과 Electron 고정 버전은 유지했다. 갱신 후 전체 테스트와 설치 파일 빌드를 다시 통과했다. `source-map-js`의 해당 보안 수정은 [공식 1.2.2 릴리스](https://github.com/7rulnik/source-map-js/releases/tag/v1.2.2)에도 기록돼 있다.

2026-10-08 npm 보안 검사 결과는 다음과 같다. 수치는 취약점이 연결된 **의존성 항목 수**이며 개별 취약점이나 실제 악용 사례의 수가 아니다.

| 검사 | 수정 전 | 수정 후 |
|---|---|---|
| 실행 의존성 검사 `npm audit --omit=dev` | 0개 | **0개** |
| 전체 검사 `npm audit` | 12개: 높음 4·보통 8 | **10개: 높음 2·보통 8** |

전체 검사에 남은 높음 항목은 `electron`, `extract-zip`이다. 보통 항목은 `@electron/get`, `app-builder-lib`, `dmg-builder`, `electron-builder`, `electron-builder-squirrel-windows`, `global-agent`, `roarr`, `sprintf-js`다. 빌드 도구의 의존성 문제와 실행기 문제를 함께 포함한다.

**Electron이 개발 의존성으로 분류돼도 실제 설치 앱의 실행기로 포함된다. 따라서 실행 의존성 검사 0개를 앱 전체의 보안 문제 0개로 해석하면 안 된다.** Electron 22는 공급자 보안 지원이 종료됐고 알려진 실행기 취약점이 남아 있다. 예를 들어 [공식 NativeImage 보안 권고](https://github.com/electron/electron/security/advisories/GHSA-6r2x-8pq8-9489)는 더 높은 버전의 수정을 요구한다. 이번 프로그램에서 해당 취약점의 악용을 재현한 것은 아니다.

Electron 23부터 Windows 8·8.1 지원이 중단되므로 강제 최신 버전 갱신으로 사용자가 정한 지원 범위를 바꾸지 않았다. Windows 8 지원을 유지할 실행 기반과 보안 유지보수 방안은 후속 개선이 필요하다. [Electron 공식 Windows 지원·보안 지원 종료 안내](https://www.electronjs.org/blog/windows-7-to-8-1-deprecation-notice), [프로젝트 호환성 문서](windows-compatibility.md).

운영 전 남은 확인 사항은 다음과 같다.

1. Windows 8·8.1·10·11의 실제 설치·최초 실행·인쇄·업데이트 후 데이터 유지. 현재 설치 파일에는 코드 서명이 없다.
2. Windows 설치 후 사용자가 직접 캠핏에 로그인해 내보내기 존재·CSV/XLSX 형식·실제 조회 범위를 확인. 모의 예약 화면 검증을 실제 공급자 검증으로 간주하지 않는다.
3. 이미 확인 대기 중인 레이트 종료 시각·기본요금 설정, PIN 분실 복구 정책.
4. 구형 실행기의 보안 유지보수와 남은 빌드 도구 의존성 정리.
