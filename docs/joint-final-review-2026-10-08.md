## 보관·검색·백업 사용

**설정 → 지난 연도 기록 보관**에서 대상 건수를 확인하고 실행한다. 한국 시간 기준으로 올해 이전에 끝난 퇴실·노쇼·취소 예약과 연결된 배정·변경 기록을 옮긴다. 도착 전·입실·예정 이동·미확인 변경이 있는 예약과 장박·사용중지·자리·시설·설정은 본 파일에 남긴다. 자동 보관이나 기록 삭제는 도입하지 않았다.

보관 파일은 데이터 폴더의 `archive/`에 저장되고 본 파일에는 크기·SHA-256 등을 포함한 목록을 둔다. 큰 연도는 파일을 나눈다. 새 파일을 확인·기록한 뒤 본 파일을 교체하며 저장 실패 시 이번 파일을 제거한다. **예약 명단 → 검색어 입력 → 보관 기록에서 찾기**로 모든 결과를 페이지별로 조회하고 상세·배정 이력·메모를 읽는다. 반복 가져오기는 보관된 예약을 다시 만들지 않는다.

설치 앱의 새 항공사진은 `assets/`에 저장한다. 예전 내장 사진은 **자리 편집 → 항공사진 위치 → 사진을 별도 파일로 옮기기**로 동일한 사진과 좌표를 유지하며 분리할 수 있다.

**백업은 JSON과 같은 폴더의 `archive/`·`assets/`를 함께 보관한다.** 사진만 있는 경우도 폴더로 내보낸다. 다른 폴더나 새 PC에서는 **백업 폴더에서 복원**으로 JSON을 선택하면 참조 파일까지 확인한다. 누락·손상 파일은 이름을 표시하고 조용히 생략하지 않는다. 정상 백업으로 손상된 현재 파일을 복구할 수 있으며 손상본은 `replaced-<시각>/`에 보존한다. 복원 도중 실패하면 교체한 파일을 되돌린다. 예전 단일 JSON 백업도 계속 복원할 수 있다.

## Claude 모델 오류와 협업 확인

Opus 5.5는 존재한다. 이 환경에서 `opus-5.5`로 시작한 시도는 모델 요청 단계에서 실패했고 소스를 읽지 못했다. 같은 Claude Code에서 정식 ID **`claude-opus-5-5`**와 **`--effort max`**로 다시 시작한 뒤 실제 소스 읽기·재현·테스트·수정이 진행되는 것을 터미널과 제공자 기록으로 확인했다. 선택값 저장 메시지는 호출 성공 여부를 확인하는 메시지가 아니었다. [정식 모델 ID](https://platform.claude.com/docs/en/models/opus-5-5/overview), [Claude Code 모델 설정](https://code.claude.com/docs/en/model-config).

새 세션 기본 모델의 잘못된 문자열도 `claude-opus-5-5`로 바로잡았고 이전 Claude 설정 파일은 별도로 보존했다. 제품 운영 프로필과 PIN은 그대로다. 협업은 [Orca orchestration 스킬](/Users/bj/.agents/skills/orchestration/SKILL.md)로 수행했다. Claude는 독립 검토·소스 수정·회귀 테스트를 맡고 Codex는 별도 재현·실제 실행기·설치 파일 대조를 맡았다. 세 작업의 식별자는 `task_b1b92787aaef`, `task_285a183cbf2c`, `task_53c882a49e3c`다.

## 남은 확인 사항

- **Windows 8·8.1·10·11 실기기:** 설치·업데이트 후 데이터 유지·인쇄·파일 잠금·백신·OneDrive·한국어 날짜 입력과 폴더 복원을 확인해야 한다. Mac 실행 및 Windows 파일 생성 결과와 구분한다. Electron 22.3.27 / Chromium 108과 Windows 8 이상 지원 목표를 유지했다.
- **실제 캠핏:** 실제 계정의 내보내기 존재·조회 범위·열·인코딩·다중 자리 표현·객실 이름을 확인해야 한다. 제목 행·CP949·숫자 연락처의 앞자리 0·‘5호’ 표기를 추정하여 변환하지 않았다. 로그인은 Windows 설치 후 사용자가 직접 진행한다.
- **연중 저장 한도:** 지난 연도 분리와 사진 분리로 누적 부담을 줄였지만 올해 자료만 16MiB에 도달하면 저장 한도가 남는다. 현재 연도 완료 기록의 수동 보관 여부는 추가 질문에 답변이 없어 적용하지 않았다. 일일 백업 보관 기간도 미정이며 자동 삭제하지 않는다.
- **원본 변경 정책:** 확정한 취소의 철회·원본 지정 객실 변경·실패한 자동 배치 재시도 등의 처리와 PIN 분실 복구는 미확정이다. 기존 현장 기록을 임의로 되돌리지 않는다.
- **보안·유지보수:** 전체 `npm audit`에는 **10개 의존성 항목(높음 2·보통 8)**이 남는다. 개발 의존성 제외 결과는 0이지만 Electron은 설치 실행기에 포함되므로 보안 문제가 0이라는 뜻으로 해석하지 않는다. Electron 22 보안 지원 종료와 서명 미적용을 [호환성 문서](windows-compatibility.md)에 기록했다. [검사 요약](review-evidence/2026-10-08/audit-summary.json).
- **낮은 우선순위:** 가져온 객체의 불필요 필드, 동시 조작 안내, 손상된 백업 설정 복구 UX, 설치 패키지의 사용하지 않는 의존성, 일부 운영 조작의 되돌리기는 추가 개선 대상으로 남는다.

0.1.12의 [이전 최종 검토](final-review-2026-10-08.md)는 당시 결과를 보존한다. 기존 화면 테스트가 설계대로 스크린샷 11개를 다시 생성했으며, 실제 Electron 테스트도 해당 실행기 스크린샷을 갱신했다.
