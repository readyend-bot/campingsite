# Windows 설치 후 자리 공백·캠핏 동기화 조사

2026-10-10 · 수정 버전 0.1.14

사용자가 Windows 설치 후 자리 정보가 비어 있고 캠핏 로그인 후 동기화가 안 된다고 보고했다. 사용자는 엑셀 내려받기까지 했지만 완료할 수 없다는 안내를 본 것 같다고 추가로 답했다. 실제 설치 버전·파일 형식·열·정확한 오류 문구는 미확인이다. 로컬 최신 배포본 0.1.13과 소스를 조사했으며 사용자 PIN·운영 데이터·캠핏 세션에는 접근하지 않았다.

## 자리 공백 원인

0.1.13 `loadState()`는 설치 앱의 저장 파일이 없으면 `emptyState()`를 반환했다. 도면은 코드에 포함되지만 **소풍캠핑장 도면 적용**을 눌러야 등록하는 흐름이었다. 도면 ID 없는 상태에서는 `upgradeSopungPlan()`도 아무 작업을 하지 않는다. 새 Windows에서 0자리는 이 코드로 재현된다.

Mac에 적용·편집한 도면은 Mac 사용자 데이터 폴더에만 있다. 설치 파일은 해당 운영 데이터를 이관하지 않는다. 수정 전 x64·ia32 `app.asar`의 제품 파일 134개는 작업 파일과 전부 일치했고 0.1.13 설치 파일의 크기·SHA-256도 기록과 일치했다. 오래된 코드가 패키징된 증거는 없었다.

저장소는 파일이 없을 때만 `null`을 반환하고 손상 파일은 오류를 낸다. 설치 제거의 데이터 삭제 옵션도 꺼져 있다. **Windows의 기존 데이터가 삭제됐다고 단정하지 않는다.** 같은 PC에 이미 저장했던 데이터가 사라진 경우에는 실제 데이터 폴더·사용자 계정·백업 확인이 별도로 필요하다.

0.1.14는 저장 파일이 없는 신규 설치에 **7개 동·140자리·15시설**을 생성·저장한다. 예약·배정·장박은 0건이다. 기존 저장 파일은 빈 상태라도 자동 재적용하지 않는다. 이미 빈 상태를 저장한 PC에서는 기존 **소풍캠핑장 도면 적용**을 사용한다. Mac의 편집 위치·항공사진까지 옮기려면 **백업 파일 내보내기 → Windows의 백업 폴더에서 복원**을 사용한다.

## 캠핏 수집 한계와 결함

현재 구현은 **CSV/XLSX 내보내기 수신 → 첫 파일의 열·상품·상태 연결 → 다음 요청에서 저장한 내보내기 컨트롤 클릭** 방식이다. 로그인 후 예약 API나 화면의 예약 데이터를 직접 읽는 수집기는 없다. 첫 연결 전에는 사용자가 캠핏 예약 목록에서 내보내기를 눌러야 한다.

기존 기록에는 실제 내보내기 존재·형식·컨트롤·조회 조건이 미검증이었다. 이번에 사용자가 엑셀 내려받기까지 했다고 확인했으므로 기능이 없다고 추정하지 않는다. 앱의 파일 수신 여부·형식·열·버튼 구조는 여전히 확인해야 한다. [공식 사업자 안내](https://biz.camfit.co.kr/)는 예약 관리·일일 예약표를 소개하지만 자체 프로그램용 수집 규격을 확인하지 못했다. 공개 [캠지기센터](https://admin.camfit.co.kr/) 접근으로는 로그인 뒤 예약 화면을 확인하지 못했다. 로그인 성공으로 실제 공급자 수집이 완성됐다고 볼 수 없다. 실제 예약 화면·내보내기 또는 제공된 연동 규격을 확인해야 한다.

추가 코드 결함은 일반 다운로드 링크(`a[href]`)를 인식하지 못하는 점이다. 파일을 받아도 첫 연결에 필요한 컨트롤이 누락될 수 있었다. 0.1.14는 공식 관리자 화면의 일반 링크도 기존의 엄격한 내보내기 이름 규칙으로 인식한다. 정확히 같은 이름의 컨트롤이 하나일 때만 자동 클릭하며 도메인·팝업·파일 형식 제한을 유지한다. **이 결함이 사용자 Windows의 원인인지는 미확인이다.**

기존에는 모든 3분 대기 실패에 같은 안내를 표시했다. 0.1.14는 첫 파일 연결, 예약 화면 불일치, 컨트롤 없음·중복, 클릭 후 다운로드 미수신 등을 구분한다. 오류에 예약 내용·전체 URL·필터·쿠키·인증 정보는 넣지 않는다. 실패해도 기존 예약은 보존한다.

사용자가 내려받기 후 완료하지 못했다고 답했으며 정확한 오류는 기억하지 못했다. [실제 버튼에 맞춘 매뉴얼](camfit-sync-2026-10-06.md)에 동기화 대기 중 내려받기·첫 연결·이미 받은 파일의 수동 가져오기·XLS 변환·실패별 확인 순서를 추가했다. 비밀번호·로그인을 다시 요청하지 않는다.

## 검증 경계

신규 도면 생성·저장·재실행·저장 실패·기존 데이터 보존은 임시 폴더에서 확인한다. 캠핏은 공식 도메인에 로컬 모의 응답을 제공하는 시험이며 실제 운영 계정·예약을 사용하지 않는다. 설치 파일 생성과 Mac 실행 검증을 Windows 실행·실제 캠핏 동기화 통과로 표현하지 않는다.

검증 결과: 운영 테스트 **95개**, 화면 테스트 **49개**, 타입·형식 검사와 빌드 통과. Mac Electron 22/Chromium 108에서 신규 도면 준비, 일반 링크 CSV 파일 수신·첫 연결·반복 동기화·오류 시 보존과 기존 보관/복원을 확인했다. Windows x64·ia32 통합 설치 파일 **Sopung-Camp-Setup-0.1.14.exe**를 생성했다. 실제 Windows·캠핏 공급자 검증은 별도다.

패키지 확인: x64·ia32의 제품 파일 각 **134/134개**가 최종 `dist/`·`electron/`과 바이트 일치하며 두 버전은 0.1.14다. 설치 파일은 **144,515,050바이트**, SHA-256 `656c6bcaf4f33ade9db476d189e6eaa29b06ee979badfebc59786428b426d68c`다.
